# CAHIER DES CHARGES FONCTIONNEL ET TECHNIQUE

## Système intégré de gestion hôtelière — PMS

**Version :** 1.0
**Type de projet :** Application web de gestion hôtelière
**Architecture cible :** Application web moderne, modulaire et évolutive
**Périmètre initial :** Gestion d'un établissement hôtelier
**Évolutivité :** Multi-hôtels / multi-sites / multi-utilisateurs

---

# 1. CONTEXTE DU PROJET

Les établissements hôteliers doivent gérer simultanément plusieurs activités :

* réservations ;
* disponibilité des chambres ;
* accueil des clients ;
* check-in et check-out ;
* facturation ;
* paiements ;
* restauration ;
* services additionnels ;
* housekeeping ;
* maintenance ;
* stocks ;
* dépenses ;
* caisse ;
* reporting ;
* gestion du personnel et des accès.

Lorsque ces activités sont gérées avec plusieurs outils indépendants ou manuellement, cela peut entraîner :

* des erreurs de réservation ;
* des difficultés de suivi des chambres ;
* des erreurs de facturation ;
* des écarts de caisse ;
* un manque de traçabilité ;
* une faible visibilité sur les performances de l'hôtel ;
* des difficultés à consolider les données.

Le présent projet vise donc à mettre en place un **Property Management System (PMS)** permettant de centraliser l'ensemble des opérations de l'hôtel.

# 2. OBJECTIFS DU PROJET

## 2.1 Objectif général

Développer une plateforme permettant de gérer de manière centralisée et sécurisée l'ensemble du cycle de vie d'un séjour hôtelier.

Le système devra couvrir le processus :

**Réservation → Arrivée → Check-in → Séjour → Consommations → Check-out → Facturation → Paiement → Reporting**

* de gérer les check-in/check-out ;
* de gérer les paiements ;
* de produire les factures ;
* de gérer les services additionnels ;
* de gérer le restaurant/bar ;
* de gérer le housekeeping ;

* de gérer les dépenses ;

# 12. RÈGLE CRITIQUE : DISPONIBILITÉ

Le système doit empêcher deux réservations incompatibles sur une même chambre.

Avant toute réservation ou attribution :

1. rechercher les réservations existantes ;
2. vérifier les dates ;
3. vérifier le statut de la chambre ;
4. vérifier les blocages ;
5. vérifier les maintenances ;
6. confirmer la disponibilité.

La vérification doit être effectuée **côté serveur**, et non uniquement dans l'interface.

# 35. CONTRAINTES D'INTÉGRITÉ

Le système doit notamment garantir :

### Réservation

Une chambre ne peut pas avoir deux réservations incompatibles.

### Paiement

Un paiement doit toujours être associé à un contexte financier valide.

### Facture

Une facture clôturée ne peut pas être modifiée directement.

### Remboursement

Un remboursement doit référencer le paiement initial.

### Stock

Une sortie ne doit pas produire un stock incohérent.

### Caisse

Chaque mouvement doit être rattaché à une caisse ouverte.

### Audit

Les opérations financières importantes doivent être traçables.

# 64. CONCLUSION

Le projet consiste à développer un **PMS moderne, sécurisé, modulaire et évolutif**, couvrant le cycle complet de gestion d'un établissement hôtelier.

L'architecture devra permettre de commencer avec un hôtel et un périmètre MVP tout en conservant la possibilité d'évoluer vers :

**Multi-hôtels → Réservation en ligne → Paiements → OTA → Mobile → BI → Comptabilité → Channel Manager**

Le développement devra être réalisé progressivement, avec validation de chaque module avant passage au suivant.

La priorité est donnée à :

**fiabilité des données + cohérence métier + sécurité + traçabilité + simplicité d'utilisation + évolutivité.**
